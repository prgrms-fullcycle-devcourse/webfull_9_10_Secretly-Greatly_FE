# Feature-Sliced Design (FSD) 아키텍처 가이드

이 프로젝트는 대규모 개발 및 원활한 협업을 위해 **FSD (Feature-Sliced Design) 아키텍처**를 간소화하여 사용합니다.

---

## 📂 폴더 구조 요약

```text
src/
├── app/          # 1. 앱의 최상단 전역 설정 및 Next.js 라우팅 진입점
├── views/        # 2. 각 URL 화면을 완성하는 페이지 컴포넌트 모음
├── widgets/      # 3. 비즈니스 단위 컴포넌트들을 조합한 독립적인 큰 블록
├── features/     # 4. 사용자의 행동/액션 단위 (API, 소켓 전송 기능 등)
├── entities/     # 5. 비즈니스 데이터 도메인 핵심 객체 (유저, 방 등)
└── shared/       # 6. 비즈니스 로직이 없는 범용 공통 디자인 UI 및 유틸
```

---

## ⚠️ 핵심 참조 규칙 (대원칙)

1. **단방향 참조 (위에서 아래로만 참조)**
   * 상위 레이어는 하위 레이어를 자유롭게 가져다 쓸 수 있습니다.
   * **반대로 하위 레이어는 상위 레이어를 참조할 수 없습니다.** (예: `entities`가 `features`나 `widgets`를 `import`하면 순환 참조 및 의존성 파괴가 발생합니다.)

2. **동일 레이어 참조 금지**
   * 같은 레이어 내부의 다른 도메인 폴더를 서로 참조해서는 안 됩니다.
   * (예: `entities/user` 컴포넌트가 `entities/room`의 파일을 임포트하지 않습니다. 두 데이터가 결합된 화면이 필요하다면 상위 레이어인 `widgets`나 `views`에서 조립해야 합니다.)

3. **Public API (입구 파일) 활용**
   * 각 기능 폴더 내부에 있는 파일들은 해당 폴더 루트의 `index.ts`를 통해서만 외부에 제공(export)하는 것을 권장합니다.
